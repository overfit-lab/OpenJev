OpenJev：基于 Qwen3-1.7B-Base 的架构、数据与训练方案
================================================

日期：2026-09-19。状态：设计提案，尚未实现、训练或进行性能验证。

详细说明：[模型架构](openjev_model_architecture.md)展开输入编译、候选结构、树形计算及输出语义；[训练流程与数据合成](openjev_training_pipeline.md)按执行步骤说明数据来源、合成配方、训练目标和验收条件。

核心选择：Qwen/Qwen3-1.7B-Base backbone + 共享标量评分头 + 按问题归一化 + 概率监督与蒸馏 + 独立后校准。先以普通 causal forward 验证决策能力，并比较 Choice 的独立候选与全候选可见方案；通过质量门槛后，再实现所选结构的树形前缀共享。

OpenJev 参考 Jev 公开的接口行为。现有资料未披露其层结构、参数量、分布变换和 RLCD 算法；本文给出我们的实现方案，数据规模、配比和超参数将通过实验确定。

## 1. 已知事实与设计依据

本地资料是 `docs/jev_info.md` 与 `docs/jev_offical.md`。补充查阅官方资料得到：

| 官方行为 | 对 OpenJev 的设计约束 |
| --- | --- |
| 输入 state 和 typed questions，不生成自由文本 | 输出 hidden state 上的数值，不调用 generate |
| 问题并行、相互独立地评估同一 state | 不允许不同问题之间发生 attention |
| Score 档位分别评估，模型不看到档位序号及相邻档位 | 档位描述作为独立候选分支；序号在模型外使用 |
| Choice 使用运行时定义的候选，最多 255 个 | 使用描述条件化的共享评分函数，不训练固定 255 类头 |
| Choice 取最大概率；Score 是档位编号的概率加权均值 | 两者可以复用一套候选分布建模 |
| Choice／Score 的 confidence 从分布计算 | 不新增 confidence 神经头；本方案返回明确命名的分布统计量，不宣称数值兼容 |
| 新架构、新 parallel sampler、新 RLCD | 只能确认对外行为和目标，不能据此确认内部算法 |

来源：[简介](https://docs.typesafe.ai/introduction)、[Choice](https://docs.typesafe.ai/primitives/choice)、[Score](https://docs.typesafe.ai/primitives/score)、[Confidence](https://docs.typesafe.ai/confidence)、[发布文章](https://typesafe.ai/blog/introducing-system-one-models-and-jev)。

工作假设是：一个通用的、问题条件化的候选兼容性模型，配合并行执行和分布输出。树形 Transformer 是我们在 Qwen 上实现前缀共享的工程选择，不是对官方底层网络的断言。Score 档位独立的证据比 Choice 候选严格独立更直接；Choice 是否需要读取完整候选集合，必须在第一轮 pilot 中验证，不能预先认定独立候选为最终主线。

## 2. Backbone 与版本选择

主线以 `Qwen/Qwen3-1.7B-Base` 初始化，从预训练权重直接进行决策后训练。后训练版 `Qwen/Qwen3-1.7B` 用作同数据、同预算的小规模消融对照。正式训练配置、tokenizer 与模型 revision 均以 Base checkpoint 为准。

Base 路线需要显式验证问题指令、候选语义及输入格式的适配能力，不能假定已有聊天模型的指令遵循能力。主线使用自定义结构化输入编译器，不依赖聊天模板、thinking 开关或先做一轮聊天 SFT。Base 也不天然保证概率更校准，仍需完整的概率训练和独立校准验证。

官方 config 的关键值：28 层，hidden size 2048，FFN intermediate size 6144，16 个 query heads，8 个 KV heads，head dim 128，词表 151936，绑定输入输出 embedding。模型卡标注原生上下文 32768；config 中 max_position_embeddings=40960 不直接作为产品支持长度。

来源：[Base 模型卡](https://huggingface.co/Qwen/Qwen3-1.7B-Base)、[Base config](https://huggingface.co/Qwen/Qwen3-1.7B-Base/blob/main/config.json)、[后训练版对照](https://huggingface.co/Qwen/Qwen3-1.7B)。正式实验固定 revision、tokenizer、软件环境和随机种子，并核对实际加载配置。

保留 embedding、28 层 attention/MLP、RoPE、GQA、Q/K normalization 和最终 RMSNorm。新增边界 token 与一个 2048→1 的共享线性评分头。推理不执行词表 lm_head；由于 embedding 权重绑定，这主要节约输出投影计算，不会凭空减少约 3 亿 embedding 参数。

首版保持 causal attention，不直接把整个模型改成双向 encoder，也不增加 diffusion、latent reasoning 或独立 cross-attention 层。这样每条根到叶路径都与原始 causal 模型的普通拼接序列兼容，便于验证权重迁移和计算正确性。

## 3. 输入编译与树形 attention

以下是独立候选方案 A 的逻辑结构。Choice 方案 B 将完整候选列表加入各自问题的共享前缀，再接每个候选的 readout 分支；具体语义和选型条件见第 5 节。Score 首版保持档位独立。

```text
[固定任务约定] [STATE] 状态 [/STATE]
 ├─ [QUESTION] type=choice 问题一 [/QUESTION]
 │    ├─ [CANDIDATE] 名称A + 描述A [/CANDIDATE] [DECISION]
 │    ├─ [CANDIDATE] 名称B + 描述B [/CANDIDATE] [DECISION]
 │    └─ [CANDIDATE] 名称C + 描述C [/CANDIDATE] [DECISION]
 └─ [QUESTION] type=score 问题二 [/QUESTION]
      ├─ [CANDIDATE] 档位描述甲 [/CANDIDATE] [DECISION]
      └─ [CANDIDATE] 档位描述乙 [/CANDIDATE] [DECISION]
```

所有 token 都是输入，一次模型计算后读取各个 `[DECISION]` 位置，不生成它们，也不生成理由或答案文本。保留自然语言 task instructions；任意 question_id 只用于响应映射，不进入模型。Choice 的有语义名称及描述进入模型；Score 的编号、列表位置只由后处理使用。

输入序列化固定：字符串保留原文，list 保留顺序，object 使用确定性序列化，边界 token 与用户文字隔离。用户文字中的特殊 token 字面量必须转义或以普通文本 token 化，不能改变结构。截断必须显式返回错误或使用记录在案的策略，不可悄悄删除证据。

令根为 S，问题节点为 Q_j，候选节点为 C_jk。token t 可以读取 token u，当且仅当：

```text
same_request(t,u) AND (
    node(u) 是 node(t) 的严格祖先
    OR (node(u) == node(t) AND local_pos(u) <= local_pos(t))
)
```

因此 S 不读取问题；Q_j 读取 S 和自己的 causal 前缀；C_jk 读取 S、Q_j 和自己的 causal 前缀。方案 A 中候选之间完全隔离；方案 B 中 Q_j 包含完整候选列表，因此各 readout 可通过祖先读取其他候选描述，但 readout 分支之间仍隔离。两种方案都保持问题之间、不同请求之间完全隔离。问题可共享其父状态，候选可共享其父问题。

RoPE position 使用树路径深度，不使用物理拼接 offset：S 为 0…S-1；每个问题都从 S 开始；其候选从 S+len(Q_j) 开始。不同兄弟节点可以有相同 position，因为彼此不可见。这可避免候选打包顺序污染分数。模型长度约束看根到叶路径，GPU 显存约束看整个打包 token 数，两者分别限制。

这相当于把很多条 `[state][question][candidate][DECISION]` 序列中完全相同的前缀计算合并。每层内各 token 并行计算，层之间仍串行。它是无输出 token 自回归的判别推理，不是常数时间，也不意味着只有一个 GPU kernel。

## 4. 数值头与三个 primitive

候选评分：

```text
h_jk = final_hidden_state([DECISION]_jk)       # 2048 维
z_jk = w^T h_jk                              # 共享线性头
p_j  = softmax(valid_logits_j / T_type)       # FP32 归一化
```

首版 head 不需要共享 scalar bias，因为同一问题 softmax 会消去它。padding 的候选必须排除；必须保留完整题目候选集合后计算损失。T 在主训练为 1，在最后独立校准阶段拟合。softmax 是 OpenJev 的基线分布变换，非官方 sampler 的已知实现。

Choice：argmax p 返回对应的输入 option ID，并返回全部概率。并列取确定性规则，记录在 API 约定中；不要随机采样导致相同请求波动。

Score：同样预测各档位概率；代码执行 score=Σ k·p_k，k 为档位序号。训练完整分布，不只对这个均值做 MSE，因为不同分布可以具有同一个均值。首版不引入 ordinal head，以保持模型不读取档位编号的结构。

Noul：编译成语义明确的 true/false 两个候选，返回 p_true。这样复用一套数值头。自定义 criteria 若存在则保留其语义。否定一致性需要专门数据和测试，不能声称不同调用天然满足 p(A)+p(not A)=1。

首版将 `1-H(p)/log(K)` 明确命名为 `distribution_concentration`，K=1 时约定为 1；不将其作为默认 `confidence` 字段或跨候选数通用的自动处理依据。它有明显的候选数效应：两个候选各占 0.5 时为 0；255 个候选中仅两个各占约 0.5、其余接近 0 时约为 0.875，而最大概率仍约为 0.5。该统计量只用于诊断，并注明 K；K=1 的值也不表示答案可靠。首版不提供未经定义和验证的 Jev confidence 兼容字段。

Choice 返回 `top_probability` 与 `margin`，以实际数据验证后的 top probability 阈值及必要的分组策略控制自动处理；这些数值本身也不保证逐样本正确。Score 额外返回档位分布方差 `Σ p_k(k-score)²`，业务代码可计算 `P(level >= b)` 等越过业务边界的概率。方差使用档位序号单位，不能直接跨量表比较；相邻档位与两端档位上的相同概率权重有相同熵，但其评分误差风险不同。Noul 保持只返回 p_true 的语义。所有自动处理阈值在独立策略验证数据上选择，冻结后才在最终测试集评估，详见第 8、12 节。

若候选可能不覆盖输入，调用者应定义 `other`、`unknown` 或 `insufficient_evidence` 的具体语义。它们并不等价，也不应由服务悄悄塞进已有封闭候选列表。动态的 `other = 不属于本题其余任何类别` 必须能访问这些类别的定义；不能把一个看不到其他选项的独立分支当成通用兜底，支持路径见第 5 节。仅凭高最大概率或低熵不能可靠检测分布外输入。

## 5. 独立候选的已知表达能力限制

独立 logits + softmax 导致：

```text
p(a)/p(b) = exp((z_a-z_b)/T)
```

在固定温度 T 下，新增候选 c 不会改变 a 和 b 的相对赔率。这种独立性假设可以作为原子分类的基线，但对动态 taxonomy、兜底类别、重叠类别、近义重复候选及“选项中最长的描述”等集合比较可能不成立。

例如某个可见输入对应 40% 的 A 和 60% 的 C：候选为 `[A, other]` 时目标为 `[0.4, 0.6]`；改为 `[A, C, other]` 时目标为 `[0.4, 0.6, 0]`。如果 A 与 other 分支的输入不变，它们的相对赔率就不变，无法同时拟合这两种目标；softmax 分母变化不能解决这个问题。候选集合相关性因此是常见分类需求，不只是特殊比较任务。

方案 A 的支持范围限定为可单独描述的原子判断。固定 taxonomy 可以把兜底类别展开成自足的明确语义，但其定义变化就必须重新编译；未展开的动态补集语义不得由 A 静默接受，应使用支持候选集合的 B，或返回明确的不支持错误。数据检查类别重复与语义重叠。新增无关候选不能要求原概率完全不变；即便 logits 不变，归一化也会改变概率。

第一轮 pilot 必须用普通 causal forward、相同数据与训练预算比较两个 Choice 结构，树形 kernel 不作为实验前置条件：

- A：独立候选评分，作为低计算量基线；是否实际更快需要测量。
- B：每个问题共享整个候选列表，然后为每个候选设置独立 readout；允许相对比较，但保留跨问题隔离。普通参考路径为 `[state][question][complete_candidates][candidate][DECISION]`。

重点评估动态增删类别、other、重叠类别、近义重复选项和未见 taxonomy，并报告分组 NLL、高置信错误与工作流风险。依赖集合语义的目标任务不能只凭总体平均分选择 A；依据预先规定的质量与成本门槛选择 B，或明确收缩 A 的支持范围。小型候选集合聚合层仅作为另行验证的备选。

B 中修改一个候选可以改变其他候选的 raw logits，这是预期行为。B 的完整候选列表采用固定的规范化顺序，分支回映射到原 option ID；只改变请求中候选排列或物理打包顺序时，编译后的语义前缀不变。普通 causal 模型并不天然对实际改变前缀次序保持不变，应另测次序敏感性。Score 的业务档位顺序始终保留。A 的表达限制属于本方案的分析，不能据此推断 Jev 的内部实现。

## 6. 实现与性能路线

先为 A／B 建立逐候选普通 causal forward 的正确性参考；训练时把同一题的所有 logits 合并后计算 listwise loss。完成小规模能力试验、选择候选结构，并通过第 12 节的 pilot 门槛后，再实现对应的树形 mask：先用小输入的明确 mask 验证，再评估 block sparse attention。树形共享用于减少重复计算，不作为决策质量提升的来源。

可以评估 PyTorch FlexAttention 的 BlockMask。它提供自定义 mask 和块稀疏计算，但并不保证这种树布局自动高效，短候选的块填充、mask 构造、GQA backward 和编译开销都要实测。[官方文档](https://docs.pytorch.org/docs/stable/nn.attention.flex_attention.html)、[官方说明](https://pytorch.org/blog/flexattention/)。

训练不能使用 detached 的推理 KV cache 代替共享前缀计算。共享前缀的梯度应汇总所有子分支。候选很大需要微批时，必须维持完整概率分母和正确计算图，或做有验证的重计算；不能逐候选各算一个独立 CE。loss 先按题归一化，再按状态／任务权重聚合，避免候选多的题自动占更大权重。

部署时可以先计算状态 KV，再分支计算问题及候选，或者整个树一次 packed forward。前者是分阶段执行，后者是单次 forward；二者都可以提供一次 API 请求。优先以实测性能选实现。状态 cache key 必须包含 checkpoint、adapter、tokenizer、序列化、精度及完整 token 内容，权重变化后旧 cache 无效。

计算量大致包括下列各项；B 的 Q_j 长度包括完整候选列表，因此不能直接沿用 A 的前缀长度、显存或性能估计：

```text
projection / MLP: O(S + ΣQ_j + ΣC_jk)
attention: O(S² + Σ(Q_j S + Q_j²)
                  + Σ(C_jk(S+Q_j) + C_jk²))
```

忽略层数、hidden size 和常数后，关键结论是共享了 state 计算，但每个候选仍然需要读取 state。问题和候选增加到 GPU 饱和后，延迟必然上升。不要承诺“任意多问题几乎免费”。

按 Qwen config、BF16 计算，仅完整 28 层 KV 就是每个 state token 2×28×8×128×2=114688 bytes，即 112 KiB；4096 tokens 约 448 MiB，不含权重和激活。如果每个候选复制一份 state KV，显存优势会迅速消失。推理实现需要实质共享，训练还要计入反向激活。

量化放在概率质量稳定之后；量化后重新测校准并拟合适用于该精度的温度。没有硬件和实际 profile 前，不给出 100ms、百倍提速或训练 GPU 小时承诺。

## 7. 数据定义：以 decision 为计数单位

一个 decision 是一组 `(state, question, complete_candidates, target)`；8 个候选的 decision 是 8 个 leaf，但不是 8 个独立训练题。一份 state 可以关联多个 decision。数据统计同时记录唯一 state、decision 数、候选 leaf 数、原始 token 数与共享后的 token 数。

建议样本结构：

```json
{
  "id": "example-001",
  "source_group": "source-doc-or-simulator-family",
  "task_family": "support-routing",
  "language": "zh",
  "state": "客户说物流显示签收，但自己没有收到包裹。",
  "question": {
    "type": "choice",
    "instructions": "哪一类团队最适合首先处理？",
    "candidates": [
      {"id": "shipping", "text": "物流、签收异常与丢件"},
      {"id": "billing", "text": "扣费、账单与发票"},
      {"id": "returns", "text": "已收到商品后的退换货"}
    ]
  },
  "target": {
    "kind": "verified_hard",
    "label": "shipping",
    "distribution": null,
    "provenance": "explicit-routing-policy",
    "quality_weight": 1.0
  },
  "evidence": ["物流显示签收，但自己没有收到包裹"],
  "teacher_runs": [],
  "transform_family_id": "family-001",
  "split": "train"
}
```

`target.kind` 至少区分 verified_hard、observed_hard、verified_distribution、human_distribution、teacher_soft、teacher_hard。verified_hard 用于经验证的确定性标签；observed_hard 用于一次真实观测或模拟采样得到的事件标签，不表示输入足以确定该事件。事件标签记录观测窗口、采样机制以及可用的选择概率，避免把选择性观测当成部署总体分布。教师意见熵／分歧单独存储，不能当成真实标签概率。evidence 标注、教师解释、隐藏模拟状态、答案与 target 全部不进入学生输入。

分类 taxonomy、候选语义、序列化版本、生成器及 verifier 版本、教师模型和 revision、采样参数、审核记录与数据许可记录都应有可追踪的元数据。模型或老师的名字不能替代质量测量。

## 8. 数据合成的八个步骤

步骤 A：先建立任务蓝图和冻结测试范围。

覆盖意图／路由、文本蕴含、政策匹配、相关性、事实支持度、实体候选匹配、评分 rubric、结构化动作选择。提取任务首版是“给定实体候选的选择”，不宣称支持任意开放字符串提取。需要计算的部分交给代码，不把长算术推理当作主体。

每个蓝图包含任务语义、类别约定、允许证据、真值生成方式、难度与域外划分。按文档、实体群组、业务规则族、模板族和反事实家族划分数据，然后再做扩增，防止近重复泄漏。划分用途固定如下：

| split | 职责 |
| --- | --- |
| train | 训练模型、监督与蒸馏 |
| dev_model | 架构、超参数、早停、calibrator 形式选择及 pilot 质量比较；后文 dev 默认指此集合 |
| calibration | 在固定模型上拟合温度等校准参数，不拟合模型权重 |
| dev_policy | 在固定模型和校准器上选择自动处理阈值与工作流策略 |
| test | 只评估已经冻结的模型、校准器、阈值与工作流，不用于选型或调参 |

dev_model 和 test 分别包含相对训练集未见的任务定义／候选 taxonomy，并保持来源组隔离。pilot 的 go/no-go 使用开发数据，最终 test 不作为循环调试反馈；因测试结果改变方案后，需要新的未使用测试数据才能给出独立验收结论。数据有限时可在开发数据内采用交叉验证，但仍保留最终独立 test。

M0 同时冻结少量目标业务的真实工作流，例如工单路由与升级、政策检查后动作选择。固定问题定义、分支逻辑、可执行动作和人工复核条件，预先定义最终动作真值、错误成本、风险上限、最低自动处理覆盖率及延迟预算。工作流代码可冻结并预留阈值参数，阈值仅在 dev_policy 上选择；具体数值来自目标业务，在训练前登记，不事后按模型表现移动门槛。

步骤 B：混合两条来源路径。

- 真实文本路径：收集可用文本，生成原子问题及候选，由独立验证器定位证据或人工审核。
- 可验证合成路径：先生成结构化事实与规则，执行规则得到标签，再生成表述；重新从表述抽取事实，验证标签所需信息未改变。

后一条不能只检查隐藏世界中的标签正确。若任务声称答案可由文本唯一确定，必须验证用户可见文本足以支持标签；不满足时重新标注为条件分布，或在题意明确允许时标注信息不足。若任务本来就是预测实际发生的事件，则允许使用 observed_hard，但不得把它解释成从文本必然推出的唯一答案。

步骤 C：生成高质量候选。

每题既要有普通负例，也要有同父类别、相近意图、单条件不同的困难负例。检查互斥性、覆盖性、描述风格、长度和信息量。不要总是把正确选项写得更长、更具体，或者固定放在第一位。Choice 对请求中的候选次序随机化以检查映射不变性；B 仍按固定规则编译完整候选前缀，另行改变该前缀次序的敏感性实验必须单独标记。Score 要保留明确的业务序关系，物理打包可以改变但必须恢复原序号映射。

Choice 初始候选数分布可设：2–4 占 40%，5–16 占 40%，17–64 占 15%，65–255 占 5%。这是数据预算建议；损失按题平均，高候选样本需要单独显存预算。Score 使用 2–10 个档位，Noul 固定为二元；不把 Choice 的候选数预算套用到所有 primitive。

在第一轮数据中加入同一 state／question 的候选集合变体，覆盖增删类别、兜底含义变化和重叠类别，按新集合重新计算目标，不盲目沿用原分布。这些变体作为同一家族划入同一 split，用于 A／B 选型与回归检查。

步骤 D：教师标注和验证。

使用一个强教师做主标注，另一独立教师只复核难例、分歧例和抽样质量。教师输出：选项、证据、候选分布、是否信息不足、题目是否不适定。教师可以在离线阶段花费推理算力，学生不学习输出推理文本。

对 teacher_soft，保留完整分布。教师口述概率是噪声标签；多次采样频率是模型采样分布，不是真实世界概率。增加采样次数不能消除共同偏差。有可验证标签时优先真值；有争议的人类任务可以保留标注者分布，但明确预测目标是标注者选择，而非客观事件。

不要给每条题都固定做 16 次教师采样。先做单次标注和验证，只对边界、冲突、学生高损失样本追加教师预算。教师输出格式验证、证据一致性验证和概率和为 1 的数值检查均自动化。

步骤 E：专门生成具有已知条件概率的数据。

构造有限的隐藏状态 z、可见观测 x、标签 y，保留明确的先验与观测机制。对于同一个 x，通过枚举或可靠模拟求 P(y|x)。给学生和教师的都是 x，隐藏 z 不进入模型输入。能可靠计算完整条件分布时，优先以 verified_distribution 监督，充分利用生成器信息并减少采样噪声。

只有一次真实事件或模拟采样标签 y 时，也可以用 observed_hard 进行 CE 训练：`E_{y~P(.|x)}[-log p_theta(y|x)] = -Σ_y P(y|x) log p_theta(y|x)`。因此，在采样机制正确的前提下，事件硬标签同样可以学习条件分布；一次结果并不表示该事件对当前输入的真实概率为 1。禁止的是输入侧泄漏隐藏信息，以及把随机实现误写成确定性知识，不是禁止合法的事件监督。选择偏差、有限数据和模型失配仍需独立检查。

例如业务模拟器中，不同隐含诉求能产生相同简短用户消息；从已知生成机制得到该可见消息对应的诉求分布。模拟器必须有多种机制和文本表述，避免只记住模板。合成环境内的校准不能替代真实业务校准。

步骤 F：制作成组扰动。

1. 同义改写、别名、语言改写：经验证语义等价时，分布应近似一致。
2. 修改决定性事实：重新执行规则或标注，答案随之改变。
3. 删除关键证据：重新推导可见信息下的标签分布；有些题应转成信息不足。
4. 加入无关文本：经验证确实无关后，保持目标不变。
5. 制造冲突证据和重叠候选：测试如何处理歧义，不盲目保留原标签。
6. state 中出现假指令、假角色边界：任务 instructions 仍决定判断语义。
7. 已知先验变化、跨领域和难负例：检验过度自信。

删除信息不保证每个样本熵都增加：删除一段冲突信息反而可能更确定。不能无条件施加“删信息必须降 confidence”的损失。同样，教师高分歧并不自动说明真实事件有高随机性。

步骤 G：过滤和去重。

过滤答案泄漏、标签与证据矛盾、候选描述无法区分、仅靠文风识别正确项、无意义数值 rubric、生成器固定位置偏差。进行精确去重与语义近重复分组。同一原文、其译文、问题改写和反事实家族必须放在同一 split。

步骤 H：主动难例循环。

用当前学生跑未标注池，选高置信错误、教师分歧、扰动不一致、高 NLL、未覆盖领域，追加验证标签，再与普通样本混合训练。不要只训练难例而改变全部类别先验。校准集保持接近部署分布；刻意过采样难例的数据不能未经修正地充当校准集。

## 9. 数据规模与配比

先做约 10 万 decision 的质量试验，再扩至 50 万–200 万 decision 的第一轮主训练。每份 state 可有 4–8 个问题，但不是每条都有；先估算共享后的实际 token 量、候选数和教师成本，再考虑更大规模。

第一轮主训练来源的起始配比：40% 可验证、人工复核或有可信观测机制的事件硬标签，35% 经验证教师标签，15% 已知条件概率合成题，10% 多标注者或明确定义的边界分布题。确定性标签与 observed_hard 分开统计。若尚无可信人类分布数据，这 10% 留空或转给有真值数据，不能用教师数字冒充。

增强标签与来源维度分开统计：约 20%–30% 的训练题可属于反事实、干扰或缺失信息家族，不在上面的 100% 之外重复计数。中英先按约 1:1 建立覆盖，再根据业务调整；校准按语言分别检查。

上下文先以 256–2048 tokens 为主，逐步加入 4K–8K；长上下文是独立扩展阶段，不因 backbone 支持长上下文就直接承诺同等能力。按长度及候选数 bucket 组 batch。

## 10. 训练步骤与损失

阶段 0：冻结评测与基线。

建立 Base 的受限候选 label 概率基线、基于 Base 的普通逐候选判别 forward 基线，以及后训练版 Qwen3-1.7B 非 thinking 的答案对照。Base 不使用 thinking 开关；各基线输入包装可以适配各自 checkpoint，但保持相同任务信息和工作流。受限 token 概率只作为基线，不把它当成天然校准概率。测试集不用于教师改写或调参。

阶段 1：读出头、结构 token 与决策指令适配。

用 2 万–5 万高质量决策题先训练评分头与新增 token embedding；先冻结 backbone，待 head 有效后解冻顶层 4–8 层或切入 LoRA。冻结时应确认只有新增 embedding 行更新，而不是不小心开放整张 embedding。前期主要使用 2–8 个清晰候选。

针对 Base，适配集必须包含“同一 state、不同问题”和“同一 state 与问题、不同候选定义”的配对任务，以及未见过的指令改写，验证模型确实读取任务定义。冻结阶段仅作短暂读出热身；进入解冻训练后，以未见任务上的判别能力和 NLL 决定是否扩量，不能仅凭简单分类训练准确率进入下一阶段。这里训练的仍是直接决策，不要求生成聊天回复或思维链。

起始 head/token LR 约 1e-4–5e-4，以 dev NLL 和梯度稳定性调整，不把这些范围当已验证配方。

阶段 2：多任务判别训练和蒸馏。

推荐主要 checkpoint 最终全参数训练；算力受限时先用 LoRA 验证方向，但不要预先断言 LoRA 质量等同全参。主线 backbone LR 可从 1e-5–2e-5 试起，head LR 约 1e-4，AdamW、warmup 3%、gradient clip 1.0、BF16，损失归一化与 log_softmax 使用 FP32。0.5M–2M decision、1–2 次遍历只是起始范围，按 dev 分布质量早停。

硬标签（verified_hard／observed_hard）：`L_hard = -log p_y`。两者使用相同损失，但保留不同的标签语义和来源记录。

有可信分布 r：`L_dist = -Σ r_k log p_k`。

教师分布 q：`L_teacher = KL(q || p)`，或等价软标签 CE。它学习教师分布，只是能力迁移目标。

同一样本只有适用的目标项参与。有可信完整条件分布时优先 L_dist；只有可靠事件或确定性标签 y 时使用 L_hard，冲突的教师目标不应与真值等权混合。teacher-only 样本用单独质量权重。在主训练中可从 teacher loss 权重 0.3–0.5 试起，后期降低到 0.1–0.2。权重以实验为准。

阶段 3：概率质量与困难样本训练。

引入 10 万–30 万经验证难例，保留约一半普通回放样本；LR 降到约 2e-6–5e-6。主目标仍保留 CE，可在有可信标签的题上增加 Brier：

```text
L_Brier = Σ_k (p_k - 1[y=k])²
L = L_supervised + λ_teacher L_teacher + λ_Brier L_Brier
                     + λ_consistency L_consistency
```

对于真实目标分布 r，可用 Σ(p-r)²；它和期望逐事件 Brier 相差与模型无关的常数。Brier 权重可从 0.1 开始，只通过消融保留；不必将多个 proper loss 堆叠当作进步的证据。

consistency 只用于已验证同义的配对输入，例如对齐候选后的 JS divergence，权重先小于主目标一个数量级。物理打包次序不变性由 mask/position 结构保证；B 的输入排列不变性还依赖候选列表规范化，不能靠额外 loss 掩盖实现错误。对反事实或改变目标分布的候选集合变体不能加分布一致性。

严格适当评分规则的理论依据是鼓励诚实的预测分布，但不保证有限样本、有限模型和分布变化下完美校准。[Gneiting 与 Raftery](https://sites.stat.washington.edu/people/raftery/Research/PDF/Gneiting2007jasa.pdf)。

阶段 4：独立后校准。

固定权重，使用不参与上述训练的 calibration 集（起点约 2 万–5 万 decision）拟合 T>0，先按 primitive 拟合少量温度参数并检查候选数与领域分组。数据不足的组不单独拟合。通过参数化 log T 保证正值，以 NLL 为目标。之后在 dev_policy 上选择阈值与策略，再冻结完整系统；最终 test 仅用于报告 NLL、Brier 与自动化风险。

温度 scaling 是基线，不保证修复错误排序或 OOD 过度自信。[Guo 等人的原始研究](https://proceedings.mlr.press/v70/guo17a)。若需要选择更复杂 calibrator，用单独 dev 或交叉验证，不反复查看最终 test。部署量化／adapter 改变后重新校准。

## 11. RLCD 的关键判断与后续 RL 路径

不能把普通“选对奖励 1、选错奖励 0”称为可靠的校准训练。假设真实 P(y=1)=0.7，模型以 p 的概率采样动作 1，期望答对奖励是 0.7p+0.3(1-p)，最大值在 p=1，而非 p=0.7。它会鼓励确定地选多数答案。

若奖励完整预测分布，例如 `R(p,y)=log p_y` 或负 Brier，其期望才以真实条件分布为最优。但当 p 可微且 y 已知时，直接反向传播即可，通常没有必要引入策略梯度的额外方差。不能把 CE 改名为 RLCD 并声称复现官方。

OpenJev v1 将上述阶段称为“校准决策训练”，不宣称还原 RLCD。PPO/GRPO 不进入主线，除非明确了其必须解决的额外问题。

需要真正环境交互时，分成两个目标：概率预测器估计环境结果，决策器根据效用选择动作。对低概率事件的探索策略、采样 propensity 和奖励日志单独记录；只观察被执行动作结果会引入选择偏差。优先在可重置模拟器中对候选做反事实 rollout 得到 outcome 标签，再训练预测器。直接优化决策收益可能让动作策略更尖锐，不能把该动作分布解释成真实事件概率。

有预算时可研究以整个概率向量为动作、按 proper score 奖励的在线校准算法，但要单独证明它比直接监督和新数据回流更有效。官方所谓 parallel sampler 是否涉及其他概率参数化，本方案没有证据作出判断。

## 12. 验收、消融和停止条件

先用普通参考模型通过 pilot 质量门槛，再验证树形优化。架构正确性必须先于大规模训练：

- 相同权重下，逐候选参考与树形实现 logits、按题 loss、梯度一致，容差根据 FP32/BF16 后端验证。
- 重新物理打包候选只改变输出顺序，不改变对应 logits；B 的规范化候选前缀必须保持相同。增加另一个独立问题不改变已有题输出。
- A 中修改一个候选不改变兄弟候选的 raw logits，最终概率可因归一化改变；B 中候选语义变化可以影响全部 logits，不套用 A 的隔离断言。
- 共享前缀梯度等价于参考中各复制前缀梯度之和，并使用相同 loss reduction。
- 多请求隔离、RoPE 深度、padding、非法候选、NaN/Inf 与特殊 token 注入都有明确行为。
- Noul 概率在区间内，Choice 只返回合法输入 ID，Score 分布和为 1 且均值计算正确。

质量评估不能只看 accuracy：报告 NLL、Brier、top-label 与 classwise calibration、可靠性图、AURC、覆盖率—错误率曲线；按领域、语言、候选数、长度、歧义与 OOD 分组报告。Score 同时检查分布与排序／均值误差，Noul 检查二元概率质量。

在接近部署分布的 dev_policy 上选择自动处理阈值，冻结后在独立 test 上报告覆盖率、错误率及置信区间。不得在 test 上挑阈值后仍把同一批结果当作无偏验收；普通置信区间不会自动修正策略选择偏差。低错误目标需要足够数量的已自动处理样本，不能仅凭小样本零错误宣称可靠；同一来源含多题时，区间估计还需处理组内相关性。分布集中度、高 top probability、校准和 OOD 检测是不同指标。

confidence 行为检查从 pilot 开始：固定主要概率质量，只增加近零概率候选，检查集中度随 K 的变化，并确保自动处理策略不把这种变化当成正确率上升；分别评估各 K、语言、领域下 top probability 阈值的风险。Score 对相邻与远距离档位的不确定性分别报告方差、业务边界概率及实际动作错误，不能只看熵。

工作流评估也从 pilot 开始，按 M0 冻结的定义报告最终动作错误率、自动处理覆盖率、人工复核率、每请求错误成本及端到端 P50/P95 延迟。单题校准不推出工作流可靠：attention 隔离不意味着预测错误统计独立，多个判断同时成立的概率不能直接取其中一个概率，也不能未经验证就相乘。需要联合事件概率时，使用有真实联合标签的预测任务，或在明确假设下估计并验证；否则直接评估整条策略的动作风险。

按实际分支经过的样本检查条件校准及错误，例如上游准入通过后的政策判断、自动通过后的动作选择；同时报告子集样本量和不确定性。校准全体样本不能替代这些子集检查，执行日志若只记录已执行动作也不能直接代表全部请求。

pilot 的 go/no-go 在 dev_model 和 dev_policy 上决定，至少满足：未见任务定义上相对固定基线的 NLL／决策质量达到预先登记的门槛；所选 Choice 结构在其声明支持的动态 taxonomy／other 场景通过分组质量检查；自动处理策略在工作流风险上限内达到最低覆盖率，且结论有足够样本支撑。未达到时先调整数据、模型或支持范围，不直接扩至百万题或投入树形 kernel。pilot 开发集结论只用于选型，不替代最终独立验收。

性能矩阵：state 长度 256/1K/4K/8K，问题数 1/8/32；Choice 候选数 2/8/32/128/255，Score 档位数 2/5/10，Noul 为二元。报告 GPU、dtype、软件 revision、batch/concurrency、编译冷启动及稳定态、模型计算与端到端 P50/P95、峰值显存和吞吐。明确 baseline 是否生成概率和理由，分别比较同等输出信息与最简决策；效率比较包含普通可用的前缀缓存方案，不能只与重复计算全部 state 的参考实现比较。

最少做以下消融：

| 实验 | 回答的问题 |
| --- | --- |
| 主线 Qwen3-1.7B-Base vs 后训练版 Qwen3-1.7B | 同数据、同预算下，两种初始化的决策泛化与校准差异 |
| 逐候选普通 causal vs 树形共享 | 工程改造是否保持数值、是否实际提速 |
| 独立候选 vs 全候选可见（pilot 前置） | 动态 taxonomy、other、重叠类别上的分布质量与工作流风险是否支持结构选型 |
| 硬标签 vs 加教师软标签 | 蒸馏是否改善未见任务，而不只是拟合教师 |
| 加已知概率／缺失证据数据 | 是否减少高置信错误并改善概率质量 |
| CE vs CE+Brier | Brier 是否有独立收益 |
| 校准前后、量化前后 | 后处理与部署精度的真实影响 |
| 单题指标 vs 完整工作流和条件分支 | 校准与准确率改善是否转化为实际动作风险和覆盖率改善 |

若独立候选方案在集合依赖任务显著失败，调整任务范围或采用候选交互方案；若教师一致性改善而真实标签表现变差，降低教师权重并补真值；若稀疏 kernel 不快，保留正确参考并优化布局，不以理论稀疏率代替性能。

## 13. 实施顺序

M0：固定数据格式、A／B 编译语义、输出统计量与 baseline；按来源组冻结 train/dev_model/calibration/dev_policy/test。选定真实工作流，登记风险上限、最低覆盖率、质量门槛与延迟预算。

M1：以 Base 初始化普通 causal 逐候选参考和共享标量头，完成基本数值和梯度检查，跑 2 万–5 万题进行读出及决策指令适配；建立 A／B 的可比较实现。

M2：约 10 万题 pilot，以普通 forward 比较不同 checkpoint、教师数据和 A／B；检查未见任务、动态 taxonomy／other、confidence 统计行为及完整工作流。使用开发数据决定 go/no-go 和 Choice 支持范围，通过后选定结构。

M3：为所选结构实现树形 mask、路径 position、共享梯度和推理布局，验证 logits／loss／梯度等价；与含前缀缓存的基线比较性能。若没有实际收益，保留普通实现，不把树形 kernel 作为产品必要条件。

M4：质量门槛通过且计算预算可行后，扩大到 50 万–200 万题，完成主训练、难例回流、独立校准及 dev_policy 上的阈值选择。工作流与分组质量检查贯穿训练。

M5：完成 serving、必要的量化与成本优化，发生精度或权重变化时重新校准并重选阈值；冻结实际部署系统后，在独立 test 上进行单题及工作流最终验收。测试后若继续按结果优化，需要新的独立测试数据。

第一阶段成功标准是：普通参考模型在未见任务上的决策质量与概率质量达到预登记门槛；所选候选结构支持声明的业务语义；真实工作流在目标风险内达到有用覆盖率。之后才判断树形实现是否与参考等价、是否带来同质量效率收益。不把“达到官方 frontier 能力”或“百倍加速”当作尚无依据的交付承诺。
