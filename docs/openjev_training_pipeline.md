# OpenJev 数据与训练计划

更新：2026-09-20。主线收束为 **准备数据 → PiSSA 直接软蒸馏 → 验证**。取消硬标签预热、硬标签继续训练及 CE／KL 混合分支。RLCD 不占训练阶段，原理未明，首版不实施。当前重点是制题质量与教师概率采集，不提前扩大模型训练。

## 1. 三个阶段

| 阶段 | 工作 | 交付 |
| --- | --- | --- |
| 1. 准备数据 | 真实聊天提取 → API 生成问题和选项 → JSON 与语义检查 → 本地教师 thinking 后完整候选打分 → 审核冻结 | 无标签题库、teacher_soft 分布、来源划分与质量报告 |
| 2. PiSSA 直接软蒸馏 | 从选定基座初始化，联合训练低秩参数、评分头与结构 token；监督只用教师分布 | 初版 OpenJev、可重载检查点与训练记录 |
| 3. 验证 | 独立开发评估、按需校准与策略选择、最终测试 | 能力范围、质量与成本、失败模式 |

只有阶段 2 更新学生评分模型。阶段 1 的制题 API 和本地教师是两个角色，不要求同一个模型；学生基座也不固定型号。公共请求响应仍沿用 [Jev 兼容字段](openjev_api_contract.md)。

## 2. 阶段 1：把主要精力放在数据

### 2.1 提取已有对话

复用现有五份冻结来源，当前 train 有 6,095 个用户轮次前缀。保留用户原话及必要历史，截到当前 user，不使用后续 assistant 回答。历史 assistant 文本只是输入材料，不当作真实世界事实。来源可能含上游合成内容，不能统称真人流量。

派生问题、翻译和共享目录继承来源分组；不从 calibration、dev_policy、test 挑训练题或调整制题提示。原始来源路径相对运行时根目录记录，本机绝对路径与凭据不写入产物。

### 2.2 API 只构造问题与候选

向 LLM API 提供聊天材料和任务配方：目标语言、问题形式、候选数量 K、选项长度／风格及上下文预算。每个前缀先生成一道题；后续允许同源多题，但限制单来源贡献，避免靠同一对话复制扩量。

要求返回一个 JSON 对象，可直接返回，也可由一个 Markdown 代码围栏包裹。对象包含 questions，字段为 type、instructions、criteria。state 由本地程序从原始来源挂接，不接受生成器重写 state。生成器不提供训练答案、概率或 confidence；这些字段不能成为监督。

解析顺序：

1. 接收完整响应，检查结束状态与输出预算；截断内容不继续补成看似合法的题。
2. 只去除完整的单个外层代码围栏（json 或无语言标记），再严格解析 JSON；不用 eval，不执行代码，不用正则拼接多个 JSON。
3. 拒绝重复键、NaN／Infinity、多个对象、无法识别的额外字段和类型错误。顶层及 questions 都须是对象。
4. 按 primitive 校验字段、非空文本、唯一候选名称、Choice 的 2–255 项、重复或近似重复描述及实际 token 预算。
5. 挂接原始 state，调用公共请求验证与编译器；记录来源、输入哈希、API 模型、提示版本、请求指纹及拒绝原因。
6. 做语义检查：贴近用户目标、候选边界清楚、无答案提示、没有无关填充、证据充分。格式正确只是入库的第一道条件。

解析或语义失败的响应隔离保存。有限传输重试与重新制题分别记账；不能不断修补候选直到教师同意，也不能把“多轮教师一致”当成独立正确性证明。LLM 可协助检查语义，检查结论不转成硬标签训练目标。

### 2.3 候选数量与多样性

首轮 Choice／Noul 预算为 80%／20%；Noul 固定二元，不计入 Choice 的 K 配额。Score 等有可信 rubric 后单独准备，接口支持不表示训练覆盖。

以下是 Choice 子集的试制目标，待 100 条验收后修订并冻结，不是部署先验：

| K 桶 | Choice 目标占比 | 主要来源 |
| --- | ---: | --- |
| 2–8 | 45% | 意图、约束、证据、行动选择 |
| 9–32 | 25% | 同领域意图集、实体与工具集合 |
| 33–64 | 15% | 经审阅的领域标签或目录 |
| 65–128 | 10% | 有清晰边界的大目录 |
| 129–255 | 5% | 支持真实任务的大候选集合 |

100 条总样本中若 Choice 为 80 条，对应 36／20／12／8／4 条；大 K 桶计划至少 2 条恰为 255 项，前提是语义与预算通过。不能满足就如实报告缺口，不以随机字符、相邻整数或无关选项凑数。桶内按固定种子采样 K，逐整数记录实际覆盖；不要求首批覆盖全部 254 个整数。

同时统计 state／question／options 语言、问题形式、历史依赖、选项格式和长度。候选长度按固定 tokenizer 的 1–8／9–32／33–96／97–256 token 分桶；长选项与大 K 不强制交叉到超出上下文。优先原有语言，翻译另行验收并保持同源分组。

大目录可由 API 构造，先检查目录边界再复用；题目始终展示完整候选。共享目录产生的相关性纳入划分记录。禁止分别对候选小组归一化后拼成一个大集合分布。

### 2.4 本地教师 thinking 与完整候选概率

首个本地教师候选为 Huihui-Qwen3.8-27B-abliterated-NVFP4-v4，模型目录通过运行时参数提供。记录权重、tokenizer 和聊天模板哈希、量化配置及推理后端版本，不把它视作远程 qwen3.8-27b 的同一版本。本地 A800 已成功加载 NVFP4 权重；采集器使用 vLLM 的 Marlin W4A16 后端，实际结果与限制见[小试报告](data_audit/pipeline_canary.md)。

对已通过质量检查的题，教师读取同一 state、question 和全部候选；不附生成器答案或旧硬标签。先生成 thinking，再在固定的答案位置读取完整词表的原始 logits，避免 temperature、top-p、惩罚或受限解码修改后的分数。

**255 项不需要新增 255 个特殊 token。** 本地 tokenizer 已实测：在固定 Answer 加冒号换行的前缀后，676 个双大写字母编码中有 562 个是单 token；已固定种子抽取 255 个不同编码。AA、AB 是示意，实际只能使用已校验的表，不能假设所有组合都成立。数字 000–254 在该 tokenizer 中均为三个 token，不作为首轮单 token 方案。

每题把原语义候选映射到编码表，用记录 ID 派生固定种子打乱映射，并保存映射。所有 K 都使用同一双字母方案，Noul 同样映射 false／true。编码仅用于教师，学生继续读取原 criteria 名称与描述，不训练固定 255 类头。

采集时须在**该题实际完整答案前缀**验证 encode(prefix+code)=encode(prefix)+[token_id]，并核对单 token 解码回原编码。现有审计只覆盖三个模板前缀，不能代替真实 thinking 上的校验。对输出字母后的下一位置取分数是错误的；必须在答案编码生成之前取分数，也不能把 API top-k 外缺项补零。

对合法编码集合 C，在同一个位置取 z_i：

```text
log_q_i = z_i / T_distill - logsumexp(z_C / T_distill)
q_i = exp(log_q_i)
```

这是条件于合法候选集合的教师分布，不是完整词表概率，也不是现实正确率。保留合法候选在完整词表中的质量、原始候选 logits 和编码映射，便于审计拒答／格式失配。合法质量异常的处理规则先小试确定，不能静默强制归一化成“高置信正确”。

本地代码表只解决 token 表示；教师能否理解并选择 255 个选项、上下文能否容纳、编码偏好是否影响排名，都要另行验收。若更换 tokenizer 后不够 255 个可用编码，再考虑固定宽度多 token 编码的完整序列打分，不能只取首 token，也不直接加未经训练的新 token。

### 2.5 分布尖锐与冻结

先用 20 条训练侧题比较 M=1 与 M=4 独立思考。每条保存原始候选 logits，离线比较 T_distill=1／2／4；先在每条思考上温度变换，再按语义名称平均概率。单次分布作为该题第一条预先确定的轨迹，不挑最好的一条。思考采样温度与标签变换温度分别记录；编码置换另作受控检查。

高置信不自动剔除，也不为了“软”强行制造歧义。记录熵、最高项、路径间分歧、编码置换敏感性、有效候选质量、耗时和显存。量化的尾部影响可用对应未量化教师的小样本对照判断。正式配方依据开发证据确定，不能把加温度直接称为校准。

原始 logits 可以离线重算分布，但不能解决错误题目或教师共享偏差。先验收约 100 条完整题目与软标签，再扩至 1K–3K。没有足够候选质量或分数完整性时停在数据阶段返工，不切回硬标签训练。

交付分开版本化的无标签题库、teacher_soft 记录、审计和 manifest，绑定题目 ID、input 哈希、候选名称、来源组与 split。思考原文只保存在本地忽略的审计产物，不进入学生输入或公开报告。具体格式与现有实现差距见[数据约定](openjev_training_data.md)。

## 3. 阶段 2：PiSSA 直接软蒸馏

从选定基座开始一次联合训练，不先跑硬标签 SFT，也不混入 one-hot CE。采用完整候选可见的 B 结构、共享标量评分头；主干 PiSSA 低秩参数、评分头及新增结构 token 行共同更新，标准 PiSSA 的残差基底与旧 embedding 行冻结。基座和注入模块可配置。

学生只读公共输入，不接收教师编码、thinking、标签或审计。首轮学生训练温度固定 1，q 为阶段 1 冻结的软标签：

```text
log_p = log_softmax(student_logits.float())
L = -sum_i q_i * log_p_i
# 与 KL(q || p) 对学生的梯度等价；q 停止梯度。
```

T_distill 是标签构造实验参数；此处有意拟合所选平滑分布，不暗指采用师生同温度及 T² 缩放的另一套蒸馏配方。推理后校准温度由独立 calibration 拟合，与这两个温度分开。

每题等权，255 个候选不获得 255 倍样本权重；候选微批须保留整题 softmax 分母及等价梯度。缺项、NaN、非法分布、输入哈希或候选映射不一致时拒绝训练；不隐式 argmax 成硬标签。

初始预算为 rank 32、alpha 64、pissa_niter_4、BF16、一个种子，先一轮，根据 dev_model 选 checkpoint。待验证的学习率起点为 adapter／新 token 行 1e-4、评分头 5e-4；不视作已确定的最优参数。单次／多次分布或温度对照若进入训练，使用相同初始化、样本交集和更新预算。LoRA 和共享计算优化留作后续，不增加必经阶段。

保存实际残差基底、adapter、评分头、结构 token、tokenizer、编译和数据版本、optimizer 与随机状态。不能把 PiSSA adapter 直接加载到未经分解的原始权重。现有严格 --resume 不用于静默改变数据或损失。

## 4. 阶段 3：验证

| 集合 | 用途 |
| --- | --- |
| train | 权重训练及训练侧工程小试 |
| dev_model | 选择检查点、数据配方和超参数 |
| calibration | 固定模型后，按需拟合概率温度 |
| dev_policy | 模型和校准固定后选择阈值及工作流策略 |
| test | 所有选择结束后的最终验收 |

报告分任务、语言、K、长度的教师分布 KL／交叉熵、教师一致率、候选置换稳定性，以及吞吐、延迟和显存。独立核验标签上的准确率、NLL、Brier、高置信错误另行报告；独立硬标签可以用于评测，不构成硬标签训练阶段。保留随机／固定位置／长度等简单评测基线。

缺少可信独立标签时不能宣称校准成功。校准不能修复错误排名；权重、量化、编译或部署精度改变后重新验证。RLCD 不属于这三步，也不把软蒸馏或温度拟合改称 RLCD。
